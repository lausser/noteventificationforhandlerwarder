# Tasks

Reference: the `spool-inspection` spec (openspec/changes/add-spool-dump/specs/spool-inspection/spec.md) for what to build, design.md for how. The spec pins argument validation, snapshot semantics, a 1-second lock cap, and the exact text/JSON output shape — each task below carries the tests its own work calls for.

## 1. Read-only dump core

- [x] 1.1 Add `src/notificationforwarder/spool_dump.py` with `dump_spool(forwarder, tag, order, limit, fmt) -> int` that derives the DB path and table name from `forwarder`/`tag`/`OMD_ROOT` using the same naming as `RuntimeConfig.build_paths()` and `init_db()`, opens the database read-only via `sqlite3.connect("file:<db>?mode=ro", uri=True)` with `busy_timeout = 1000`, and returns the exit code — verify by a unit test that, given a temp `OMD_ROOT` with a pre-created spool file/table and seeded rows, `dump_spool` returns 0 and reads the correct table for a given `(forwarder, tag)` pair.
- [x] 1.2 Implement the ordered/limited SELECT (`ORDER BY timestamp <dir>, id <dir>`, `LIMIT` only when a valid limit is given) and take `total` and the listed rows from one consistent read — a single `BEGIN ... COMMIT` (deferred) transaction holding both `COUNT(*)` and the `SELECT` — so `total` and the list describe one snapshot — verify by unit tests that, for seeded rows with controlled timestamps, default order is oldest-first, `newest` is newest-first, same-timestamp rows tie-break by `id`, `limit` caps the rows after ordering, no limit returns all rows, and `total`/`shown` agree with the snapshot (e.g. `total=12 shown=5` with limit 5).
- [x] 1.3 Enforce the 1-second lock cap: if the database stays locked beyond the cap, take the unreadable-database path (non-zero, no record data on stdout) — verify by a unit test holding a write lock in another connection past 1 s and asserting a non-zero return with an error on stderr and empty stdout.

## 2. Argument validation and exit discipline

- [x] 2.1 Validate arguments before any query: `--order` only `oldest`/`newest` (default `oldest`), `--limit` an integer >= 1 (zero, negative, and non-integer are usage errors), `--dump-format` only `text`/`json` (default `text`), and the forwarder argument present in dump mode — verify by unit tests that each invalid value returns a non-zero exit code with a usage message on stderr and no record data on stdout, and that valid/omitted values apply the documented defaults.
- [x] 2.2 Ensure no record data reaches stdout on any non-zero exit (usage error, unreadable DB, missing table) — verify by unit tests asserting stdout is empty for each non-zero path.

## 3. Record rendering and formats (pinned)

- [x] 3.1 Decode each `payload` independently with `json.loads`, isolating failures so one corrupt record does not abort the dump; an undecodable record is still listed, counts toward limit/shown, carries `payload: null` plus `undecodable: true` and `raw_prefix` (first 120 chars, control chars escaped) in JSON and the same marker+prefix on its single line in text — verify by a unit test that seeds one non-JSON `payload` among decodable rows and asserts every record is still listed, the corrupt one is marked undecodable with the 120-char prefix, and `dump_spool` returns 0.
- [x] 3.2 Show the spool time verbatim (the stored `timestamp` string, UTC; no local-time conversion or reformatting) and state the UTC unit in the human header — verify by a unit test that, for a stored timestamp `2026-11-06 02:14:03`, both text and JSON show exactly `2026-11-06 02:14:03`.
- [x] 3.3 Emit the text format: the header (database path, table, order, total, shown) on **stderr** written **before** the first stdout record, then exactly one physical line per record on **stdout** — `#<id>  <spool_time>  <payload>` with `<payload>` one compact single-line JSON encoding (`json.dumps(..., ensure_ascii=False)`), decodable payload not truncated, no pretty-printing — verify by unit tests that stdout is one line per record (a multi-line / newline-containing payload stays one line), the header is on stderr and precedes the first record, and non-ASCII characters are preserved as characters.
- [x] 3.4 Emit the JSON format: the same header on **stderr** and one parseable JSON array on **stdout**, one element per record with keys `id` (number), `spooled_at` (verbatim), `payload` (decoded value); empty spool → stdout is `[]` — verify by a unit test that `json.loads(stdout)` succeeds, yields one element per spooled record with exactly the keys `id`/`spooled_at`/`payload` (plus `undecodable`/`raw_prefix` for corrupt rows), and that an empty spool yields `[]`.

## 4. Empty, missing, missing-table, and unreadable spool handling

- [x] 4.1 Treat a missing spool database file and an empty table as a healthy outcome: report the spool empty on stderr, including the resolved path and table, and return 0 — verify by unit tests that a forwarder with no spool file and one with an empty table both return 0 and report empty on stderr with the path and table named.
- [x] 4.2 Treat a file that exists but lacks the expected table, and an unreadable database (locked beyond the 1-s cap, or corrupt), as errors: report on stderr (naming the path and the missing table where relevant) and return a non-zero exit status — verify by unit tests (a pre-created file with no table, a pre-corrupt file, and a held write lock) that `dump_spool` returns non-zero, writes the appropriate error to stderr, and does not report the spool as empty.

## 5. CLI integration

- [x] 5.1 Add `--dump-spool` (action flag), `--order` (default `oldest`), `--limit` (int), and `--dump-format` (default `text`) to `bin/notificationforwarder`, and branch: when `--dump-spool` is set, require the forwarder argument (omit the `syslog` default; omitting it is a usage error), then call `spool_dump.dump_spool(args.forwarder, args.forwardertag, args.order, args.limit, args.dump_format)` and `sys.exit` with its return value, without loading the forwarder/formatter/reporter or running `forward`/`forward_multiple` — verify by a subprocess/CLI test (temp `OMD_ROOT`, seeded spool) that `--forwarder <f> --forwardertag <t> --dump-spool` prints the spool, that omitting `--forwarder` is a usage error (non-zero, no record data), that `--dump-spool` does not invoke the forwarder (destination never contacted, no formatter error), and that exit codes match the core (0 for empty/missing, non-zero for unreadable).
- [x] 5.2 Confirm the dump runs with the same parameter set as a regular notification command, requires no `--eventopt`, and is rejected like the regular command when outside an OMD environment — verify by CLI tests that `--forwarder <f> --forwardertag <t> --dump-spool --order newest --limit 5` (no eventopt) dumps only the selected instance, and that a non-OMD environment yields a non-zero exit that is not reported as an empty spool.
- [x] 5.3 Confirm the dump reads the spool even when the named forwarder module cannot be imported — verify by a CLI/unit test with an unloadable forwarder name and a seeded spool that the dump still lists the records.

## 6. Read-only guarantee and regression

- [x] 6.1 Verify the dump never mutates the spool and does not take the flush lock — a test that snapshots the table rows (id, timestamp, payload) before and after `dump_spool` on a non-empty spool and asserts they are identical, and that the read completes without acquiring the fcntl flush lock (e.g. with a concurrent flush lock held).
- [x] 6.2 Confirm the dump shows only stored content: no failure-reason field, no forwarder options read, no computed expiry — verify by asserting the output for a record carries no reason/expiry fields (JSON) and the operator-facing text contains no expiry string.
- [x] 6.3 Add `tests/test_spool_dump.py` covering the capability end to end (ordering, limit, validation, snapshot totals, both formats, corrupt record, empty/missing/missing-table/unreadable, lock cap, exit codes, read-only integrity) following the existing test conventions (temp `OMD_ROOT`, pre-populated spool), and run the notificationforwarder test suite plus the focused flake8 gate — verify the full `pytest tests/ -v` passes and `flake8 --config .flake8 src/notificationforwarder --count --statistics` is clean.
